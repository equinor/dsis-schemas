# Conventions

Patterns that repeat across nearly every entity. Learn these once and most of the model reads itself.

## Identifiers

| Column | Meaning |
|---|---|
| `native_uid` | The entity's primary key. Usually the OpenWorks internal id (e.g. `WellLocation.well_location_id` for **Well**, `FaultPlane.fault_plane_id` for **FaultPlane**). Generated by the server on insert — never set it yourself. |
| `alternate_uid` | A second, globally unique id taken from the native table's own `native_uid` column. Read-only. Useful for cross-project references. |
| `<entity>_native_uid` | A foreign key to the parent, e.g. `wellbore_native_uid` → **Wellbore**. |
| `*_uwi`, `*_name` next to a `*_native_uid` | Convenience copies of the parent's human-readable key (e.g. `wellbore_uwi`, `fault_name`). Normally read-only — set the `*_native_uid` instead. |

Some keys are composite: **WellCoreAnalysis** builds its `native_uid` with the `composeNativeUid(wellid, coreid, datasource, aon, saon)` function.

## Data source = interpreter / version

`data_source` (FK → **DataSource**) appears on almost every interpreted object. In OpenWorks it is the "interpreter" tag that lets several versions of the same thing coexist (two interpreters picking the same top, two versions of a fault). Some entities also carry `original_data_source` (where it was first created) and `interpretation_version_name` / `interpretation_status`.

## Units

Measured values come in pairs:

- `ground_elevation` + `ground_elevation_unit` — the value column has a `unitField` option pointing at its unit column.
- Unit columns have a `unitType` (e.g. `elevation`, `percent`, `length`) describing the quantity class.
- Some units are chosen dynamically via `unitTypeAttribute` (e.g. **SyntheticSeismic** `offset_value_unit` depends on `offset_unit_type`).

Unit strings are DSDS unit names (native columns end in `_dsdsunit`).

## Coordinates, CRS and z-domain

- `x_coordinate`/`y_coordinate` (or `x`/`y`) are in the CRS named by `crs` (FK → **CartoReferenceSystem**), with units in `xy_unit`.
- `z_domain` says whether z is **time** or **depth**; `z_domain_qualifier` refines it (e.g. TVD vs TVDSS). `datum`/`datum_unit` give the vertical reference.
- On insert, the CRS name is mapped to an OpenWorks CRS; if no mapping exists the trigger raises *"The given crs value … does not exist in OpenWorks"*.

## Read-only columns

Columns marked `isCreatable=false` / `isUpdatable=false` are computed or copied from parents: audit columns (`create_date`, `create_user_id`, `update_date`, `update_user_id`), `native_uid`, `alternate_uid`, display copies of parent names, and derived geometry (`spatial`, `*_location_point`, bounding boxes).

## What you can write

Writes go through INSTEAD OF triggers that translate into native OpenWorks inserts/updates/deletes.

| Capability | Entities |
|---|---|
| Full read/write (S/I/U/D) | 80 entities — most wells, logs, interpretation and planning data |
| Read-only | `CartoReferenceSystem`, `Company`, `Project`, `ProjectAccess`, `ProjectDBUser`, `DataSourceUserPermission`, `ProcessDataType`, `RProcessType`, `RProcessParm`, `FaultPlaneTrimesh`, `FaultTrimesh`, `SurfaceGridExtendedProperties`, `WellElevationInfo`, `LogCurveQualifier`, file/Recall entities (`Film`, `LogFile`, `WellFile`, `Tape`, `TapeFile`, `Zonation`, `ZonationFile`, `Zone`, `ZonalParameter`), concept views (`Concepts`, `ConceptPlans`, `ConceptSites`, `ConceptSiteOutlines`, `ConceptTargets`), helper views (`plannedwellslots`, `tmpwellplanview`, `wellplanlocation`, `WellPlanSiteInfo`), `PolyTarget` |
| Insert + update, no delete | `ControlPoint`, `MappingPolygonSet`, `Seis2DLine`, `Seismic2DSurvey` |
| Insert + delete, no update | `RelativeUncertainty` |
| Insert only | `WellList` |

## Binary payloads

Bulk data lives in BLOB columns. Many are "complex types" whose structure is declared in the DDL (`elementType` + `elementStruct`):

| Entity.column | Structure |
|---|---|
| `Well.surface_location_point`, `Wellbore.bh_location_point` | POINT (x, y) |
| `DirectionalSurvey.data` | arrays: md, tvd, azimuth, inclination, x/y offset, x/y/z bias, 6 covariance terms |
| `PositionLog.data` | arrays: md, tvd, x_offset, y_offset |
| `TimeDepthTable.data` | arrays: md, time, depth, x_offset, y_offset |
| `LogCurve.data`, `WellLog.data` | depths (double[]), values (float[]) |
| `FaultSegment.data` | ThreeSpaceCoordinate: x[], y[], z[] |
| `FaultTrimesh` / `FaultPlaneTrimesh` | `vertices` (x[], y[], z[]) + `triangles` (vertex_1..3 index arrays) |
| `MappingPolygon.data` | x[], y[], z[], throw_direction[] |
| `Seis2DLine.shotpoints` / `mappings` | shotpoint→x,y and shotpoint→trace |
| `WellCoreAnalysis.data` | ~50 per-sample arrays: porosity, permeabilities, saturations, densities… |
| `WellCoreDescription.data` | per-interval lithology, porosity type, shows, dip… |
| `HorizonData*.data`, `Wavelet.amplitude`, `SyntheticSeismic.amplitude` | float arrays |
| Seismic volumes, grids, point sets, files | opaque `application/octet-stream` |

Several of these are protobuf-encoded on the wire — see [PROTOBUF_GUIDE.md](../../PROTOBUF_GUIDE.md).

## Functions and procedures

- `composeNativeUid(...)`, `getCrsNameFromBlob(blob)` — Java UDFs.
- 34 virtual procedures for things a view can't do: partial bulk reads (`HorizonData3DRead`, `HorizonData2DRead`), log curve writes (`LogCurveWriteProtoBuf`), CRS conversion of plans (`convertWellPlanToTargetCRS`), deviation computation (`ComputeDeviationFromWellhead`), seismic file location/size (`LocateSeismicFile`, `SeismicFilesSize`, `GetSeismicMountInformation`), user project listing (`UserProjects`).
